<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| deployment manifest -> domain | Untrusted deployment data supplies dates, captain npubs, starting week, and allowlist values. |
| browser identity -> signer/repository | A local key requests a captain-only signed state mutation. |
| Nostr relay -> repository/parser | Arbitrary relay events cross cryptographic and semantic validation before becoming week state. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Spoofing | `buildWeekConfigurationEvent` / `parseWeekConfigurationEvent` | high | mitigate | Require canonical event verification plus `event.pubkey === slot.captainPubkey` at the repository/parser boundary and cover wrong-key fixtures. |
| T-01-02 | Tampering | kind 30078 `d`/`t` coordinate | high | mitigate | Derive coordinate from validated manifest data, accept exact kind/author/`d`/app tag only, and never accept route-supplied captain identity. |
| T-01-03 | Tampering | revision publication | high | mitigate | Refresh exact coordinate, compare `base_event_id`, use monotonic timestamps, and retain the draft on stale or failed publication. |
| T-01-04 | Elevation of privilege | `DemoDayApp` captain controls | high | mitigate | Treat hidden controls only as presentation; builder, parser, and repository each enforce manifest assignment independently. |
| T-01-05 | Denial of service | manifest/config JSON parsers | medium | mitigate | Bound strings, arrays, counts, identifiers, and supported versions before indexing/rendering. |
| T-01-06 | Information disclosure | signed public week payload | medium | mitigate | Serialize public week configuration only; exclude allowlist, secret keys, proposal content, and later-phase private state. |
</threat_model>
